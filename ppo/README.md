# ppo —— 抓取重试策略

这一层回答一个问题：**这一趟没抓住，下一趟换什么。**

- `policy.py`：重试账本。不限次数，每次只换一个变量，按实测精进。
- `guard.py`：定位一致性。方块只会被爪子碰动一点，新认出来的中心跳得太远就按认错处理。

## 现在怎么用

采集模式（面板 `--collect`）一开，`panel/rig.py` 就建一个 `RetryPolicy`：

1. 每趟开跑前 `choose()` 拿这一趟的动作（策略名 + 要不要「先量一眼」）；
2. 跑完 `observe(out)` 收实测数：6 号舵机停在几度、方块被推走多少、下探之后中心在哪；
3. 锚点写到 `skills/pick_real/knobs.ANCHOR_XY`，技能下一次认目标时按 `guard.py` 卡住。

停止条件只有三种：人手停、目标找不到（`找不着`）、设了次数上限（默认不设）。

### 动作表

| 档 | 策略 | 先量一眼 | 相对上一档 |
|---|---|---|---|
| `baseline` | `oneshot` | 开 | 起始档 |
| `no_measure` | `oneshot` | 关 | 只关掉「先量一眼」 |
| `full` | `full` | — | 换成完整微调 |

三档都试过之后，回到**实测开口最大的那一档**（开口越大，离夹住越近），
锚点和下探终点每一趟都会更新，所以重试不是原样重放。

### 定位上限

`guard.MAX_JUMP_MM = 60.0`，依据是 2026-10-20 真机 8 趟里单趟最大位移 33.3mm。

## 以后换成 PPO

`choose()` 的返回值就是 `(Action, 说明)`；把这一个方法换成策略网络的输出、把
`observe()` 里那条 `rec` 喂进 replay buffer 即可，`panel/rig.py` 的调用点不用动。
动作空间可以先就这三档，也可以扩成 `Action` 里的四个字段。
