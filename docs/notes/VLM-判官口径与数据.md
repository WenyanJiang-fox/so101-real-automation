# VLM 的作用：口径与数据

## 结论

2026-10-25 起改成判官式：VLM 只回答「方块在不在两爪之间」，答「否」就把臂抬回悬停点重下一次，别的什么都不碰。离线留出集 92.9%；线上 14 次提问里它拦了 2 次，两次都没抓成，判「是」的 11 次里 9 次仍失败 —— 主因是合爪之后的滑落，不在它的判据里。详见下面「判官式」一节。

## 分工（2026-10-23 用户定）

- **绝大部分由我们的三档策略自己决定**：用哪一档、怎么走、什么时候换档，VLM 不参与。
- **VLM 只提少量变量**，且只有两类：
  1. 感知偏移 `nudge_dx_mm / nudge_dy_mm`（±30mm）；
  2. 安全限幅 `joint1_step_deg / step_deg`，只准往小压。
- **变量只作用下一集**：下一集跑完，下一集的下一集开头无条件还原，之后的策略完全不受影响。

## 口径

以**集**为单位，全部从采集日志现场统计，脚本 `_vlm_tally.py` 可复算。

| 名词 | 定义 |
|---|---|
| 干预 | 一行 `[VLM·*] 应用`，即 VLM 的输出通过 `vlm.check` 并写进旋钮 |
| 有效干预 | 干预的 `params` 非空，且至少一个值与施加前的值不同 |
| 干预后 1 集 | 紧接触发集的下一集——**变量唯一生效的那一集** |
| 全 run 基线 | 同一个 run 的整体成功率 |
| 提前撤销 | 下一集还是同一个失败码，`_revert_if_repeated` 不等自动复位 |

主指标：**有效干预的下一集成功率 vs 全 run 基线**。
（旧口径的「前 3 集 / 后 3 集」保留在脚本里，但变量已被限定只作用一集，3 集窗口不再对应实际生效范围。）

## 三条防错闸

1. **候选门**：`nudge_candidates()` 用这一趟实测的方块位移（≥2mm）算出允许的方向；
   `vlm.check()` 拒收表外方向。程序拿不到下探前后的两个中心时表为空，位移类一个都不能选。
2. **幅度由程序定**：模型只选方向，挪多少取 `box_center_after_mm − center_before_mm`
   的实测分量（±30mm 上限）。
3. **只作用一集**：`_vlm_episode_begin` 在带变量的那一集跑完后，于下一集开头无条件还原；
   `_revert_if_repeated` 在同一个失败码复发时提前一集撤销。

另有两条只允许「更小」的约束：限幅类不许调大；档位、悬停高度、下探深度已经不在 VLM 的枚举里。

## 已知局限

- 干预次数少：只有三档全失败的集才会调 VLM。
- 成功率受方块落点、光照、臂的初始位姿影响；跨 run 直接比不可靠，**同 run 基线**才是主指标。
- 方块被推进死角后，任何旋钮都救不回来；这类集要从分母里单独看。

## 判官式（2026-10-25 起生效）

### 它只干一件事

下探到位、合爪之前问一次：**方块在不在两爪之间**。输出 `{"between": "yes|no|unsure"}`，问 2 次，两次一致才算数，不一致记 `unsure`。只有 `no` 触发动作：把臂抬回悬停点、重新下一次，再问一次但不带否决权。`yes` / `unsure` / 超时一律放行。它不改档位、不给偏移、不留变量。

### 模型

Qwen3-VL-4B-Instruct + LoRA（rank 16、alpha 32、dropout 0.05、all-linear、`freeze_vit false`），`swift sft`，10 epoch = 280 步，lr 1e-4，peak 13.25 GiB。

训练数据：`out/vlm_gallery` 的成对图，220 训 / 28 留出，留出集用 `FIXED_VAL=1` 固定成 v2 那 28 条，两版可直接比。

| 存档 | 留出准确率 | 错条 |
|---|---|---|
| ckpt-140 | 23/28 = 82.1% | 0,3,11,18,20 |
| **ckpt-210（部署这个）** | **26/28 = 92.9%** | 3,11 |
| ckpt-280 | 24/28 = 85.7% | 0,3,11,18 |
| v2 ckpt-190（145 训） | 24/28 = 85.7% | 0,3,11,17 |

评测只能走 `swift infer --infer_backend pt`；训练和部署抢显存（部署约 10.6 GiB），不能同时开。

### 已知盲区（本轮的事实结论）

8 次失败是 `slip`：合爪之后方块没在爪里，或者抬起来掉了。判官问的是合爪**之前**「两爪之间有没有方块」，这类失败它看不见，所以 8 次全答 `yes`。要覆盖这一类，得在合爪之后、抬升之前再问一次「爪里有没有方块」，或者把线上滑落样本混进去训 v4。

### 同批次的另一件事：3 号肘 75° 闸误伤摆件

同一批 run 里新加的「两臂夹角 ≥ 75°」（= 3 号肘 ≥ +1.2°）在摆件阶段触发了 4 次，原文：

```
⛔ 安全闸：3 号肘要到 0.5°，两臂夹角只剩 74.3°（下限 75°）
⛔ 安全闸：3 号肘要到 0.8°，两臂夹角只剩 74.6°
⛔ 安全闸：3 号肘要到 -1.9°，两臂夹角只剩 71.9°
⛔ 安全闸：3 号肘要到 0.3°，两臂夹角只剩 74.1°
```

这 4 集都已经抓起来了，倒在放下的路上。逆解已经按这两条下限夹过（`safety.clip_bounds`），够不着的姿势会走到「够不着」那一支；这里触发的是摆件的目标姿态本身就在限位内侧。**是否只在抓取侧守 75°、摆件侧放宽，需要用户定。**
